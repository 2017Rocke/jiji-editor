吉吉编辑软件 v0.3.3：修复用户目录不可写导致的启动失败。

### 本次更新

已收到的诊断确认：程序在准备用户目录时出现 `0x80070005`（拒绝访问），后台服务和 WebView2 尚未开始初始化。

- 默认用户目录不可写时，自动尝试软件旁按当前账户隔离的私有数据目录。
- 自动候选仍不可用时，可通过系统窗口选择可写的本机数据位置。
- 编辑窗口缓存、后台临时文件、会话文件和诊断报告统一使用选定目录，避免后续再次使用不可写的系统临时目录。
- 保留具体失败阶段及“复制诊断信息”。无需管理员运行或另外安装依赖。

这次修复针对已经确认的目录访问失败。自动测试会制造真实权限拒绝并验证回退后的编辑与导出；尚未在用户的 Windows 10 1809 机器完成验证，其他系统限制仍可能需要进一步排查。

### 已有 Windows v0.3.1 / v0.3.2

下载 `JijiEditor-0.3.3-Windows-startup-update.zip`：

1. 导出文档并退出吉吉。
2. 将 ZIP 中全部文件解压到原 `JijiEditor.exe` 所在文件夹，选择替换同名文件。
3. 双击原文件夹中的 `JijiEditor.exe`。若提示选择数据目录，请选一个可写的本机普通文件夹。

已在 v0.3.1 上应用过 v0.3.2 启动补丁的用户也适用。小型更新不能独立运行，不适用于 v0.3.0 及更早版本。它保留原有文档处理与显示组件；诊断版本变为 0.3.3，编辑页仍显示原完整包的 0.3.1 或 0.3.2，属于正常情况。原 `Source.zip` 保留，启动更新源码另附于 `Startup-update-Source.zip`。

### 首次使用或整体更新

- Windows 64 位 Intel/AMD：`JijiEditor-0.3.3-Windows-x64.zip`，完整解压后运行 `JijiEditor.exe`。
- Mac Apple Silicon（M 系列）：`macOS-arm64.zip`。
- Mac Intel：`macOS-x86_64.zip`。

Windows 完整包包含 .NET、WebView2、Python 与 PDF 引擎，无需另装这些组件或选择浏览器。PDF 编辑可离线使用。完整更新请替换整个应用文件夹，不要只移动 EXE。下载包提供对应源码、第三方许可与 SHA-256 校验值。

### 验证与限制

发布流程包括核心测试、更新依赖一致性测试、打包后 PDF 引擎与原生窗口验证。Windows 测试覆盖正常启动、默认数据目录和临时目录被拒绝访问后的自动回退、批量裁剪、撤销、保存、关闭保护和应急导出。测试用转换器验证后台真实临时文件路径，不代表真实 Office 转换质量验收。一个小型更新 ZIP 会实际覆盖到三个历史基底后再运行验证。

自动测试系统为 Windows Server 2022，不能替代 Windows 10 1809 实机。未购买商业代码签名，Mac 未经 Apple 公证，目标 macOS 13+。Word/Excel/PPT 转 PDF 仍需独立安装 LibreOffice，PDF 编辑不需要。退出前请导出文档。
